1. Goal and definition of done

After phase 3 a reader can see a criterion fail and pass in the same interface fragment, read the code of both, and learn what a screen reader says in each. The criterion page links to its examples, so explanation and practice sit one click apart.

Done when:

  • The ten starter examples render, both variants in labelled sandboxed iframes.
  • A test confirms that nothing from a broken example reaches the accessibility tree of the host page, and axe on every example page passes with the broken iframes excluded.
  • Every good variant passes axe on its own, and every broken variant that axe can detect fails with the rules it declares.
  • Every example that moves or changes on its own starts only on request.
  • The home page opens with the fix-first cards instead of the three doors.

3. Example format

One folder per example in content/praktyka/<slug>/, with three files:

content/praktyka/ikona-jako-przycisk/
  index.md    frontmatter, introduction, notes per variant
  bad.html    the broken fragment
  good.html   the fixed fragment
---
title: Ikona jako przycisk
summary: Znak × bez nazwy. Daj przyciskowi nazwę, ikonę schowaj przed czytnikiem.
criteria: ["1.1.1", "4.1.2", "2.5.8"]
effort: 1 linia
gain: Czytnik mówi „Zamknij okno, przycisk” zamiast milczeć.   # the yellow edge on the card
motion: false                      # true: the iframes start only on request
status: szkic
bad:
  why: Ikona wstawiona jako tekst, bez nazwy. Cel 20 na 20 pikseli.
  announces: Nic. Element nie jest kontrolką, więc „×” przeleci jako zwykły tekst, a Tab go pominie.
  axe: [button-name]               # rules axe must report; empty when axe cannot see the fault
good:
  why: Prawdziwy button z nazwą. Ikona schowana przed czytnikiem.
  announces: „Zamknij okno, przycisk”. Element jest w kolejności Tab i reaguje na Enter oraz spację.
---
Przycisk zamykający okno, w którym cała treść to znak ×. …

The HTML files are fragments: markup, plus an optional <style> and <script>. The code shown on the page is the same file the iframe renders, read at build time, so the demo and the code cannot drift apart. Frontmatter is validated with ArkType like criteria: unknown criteria, a missing variant file or an unknown axe rule fail the build. The body is Markdown with glossary links, rendered by the same parser.

effort and gain feed the catalogue cards (variant B): the effort label and the yellow edge with what the user gains. The catalogue is ordered by effort, cheapest first, using a fixed scale: 1 linia, 1 token, 2 minuty, 15 minut, refaktor.

4. Rendering and isolation

  • Both variants in iframes. As agreed: <iframe sandbox="allow-scripts" srcdoc="…" title="Przykład zepsuty: Ikona jako przycisk">. No allow-same-origin, so a fragment cannot read or change the host page, and no allow-top-navigation or allow-popups.
  • A small document around each fragment: lang="pl", a neutral demo stylesheet with the app's fonts and colours, and a script that reports the content height to the parent through postMessage. The parent resizes the iframe, so zoom and reflow (1.4.4, 1.4.10) do not cut the demo off. Before the script runs, a minimum height keeps the frame usable.
  • Labels around the frame, not only in it: each variant is a section with a heading ("Zepsute", "Poprawne"), the "why" note, the iframe, the code in a details disclosure, and "Czytnik ekranu powie". A screen reader user hears the description before entering the broken frame.
  • Examples that move (motion: true) render a static first state and a "Uruchom przykład" button inside the iframe. Our own page must still meet 2.2.2.

5. Rules for broken examples

A broken example is broken on purpose, but it lives inside our page, so it must never break the page itself. Every broken example:

  • never traps keyboard focus with no way out: the modal example shows focus escaping behind the dialog, the more common fault, instead of an inescapable trap;
  • never plays sound, moves or flashes before the reader starts it, and never flashes more than three times a second;
  • never loads anything from the network and never navigates away;
  • is described in text next to the frame, so nobody has to experience the fault to learn about it.

These rules go into the content README and are checked in review. The axe and isolation tests in section 8 catch the rest.

6. Pages

  • /praktyka: the catalogue as cards ordered by payoff, variant B from the mocks. Each card has a small static picture of the fault, hidden from screen readers, so the title, fix and gain carry everything. The card is one large target: the title link is stretched over it, as on the home page. It replaces the placeholder.
  • /praktyka/$slug: the reference frame in the mocks, adapted from screen 3: title, introduction, criteria as links, the draft badge, the two variants side by side on a wide screen and stacked on a narrow one. Prerendered like criterion pages.
  • Criterion page, section "Przykład": replaces the placeholder with the examples that list the criterion, as links with their summary. No iframes on the criterion page, so it stays light.
  • Home page /: follows screen 0 of variant A ("nowa wersja"). The hero becomes "Zacznij od tego, co psuje najwięcej." with the lead and the existing search field. Below it, "Napraw to najpierw": the six cheapest examples as the same cards as the catalogue, one shared component. The remaining examples follow as a compact list, ordered the same way, and a link leads to /praktyka. The three doors go: criteria, law and practice stay in the main navigation.
  • Search: examples join the index with title, summary, notes and criteria, as a third result group, "Przykłady".

8. Tests

  • Content (Vitest): every example folder parses, has both HTML files, and lists existing criteria; declared axe rule ids exist in axe-core.
  • Isolation (Playwright): on every example page, the host document's accessibility tree contains no node from a broken fragment; the fragments carry a marker attribute to check against.
  • Axe on pages: /praktyka and every example page pass with broken iframes excluded.
  • Axe on fragments: every good.html passes on its own; every bad.html reports at least the rules in its axe list. This proves the broken examples are broken in the way the text says.
  • Keyboard: the modal and the drag examples work from the keyboard in their good variant; the carousel does not move before "Uruchom przykład".
