1. The app today

  • TanStack Start, React 19, Tailwind v4. Tokens live in src/styles.css as hex values through light-dark(), mapped into @theme inline. Every text pair meets 7:1, control borders 3:1.
  • Type: Inter Variable (@fontsource-variable/inter) and the system monospace for criterion numbers, articles and dates.
  • Accent is navy #2c36a8. Yellow --color-marker has one meaning: what the user gains.
  • No motion library. prefers-reduced-motion is honoured, the app meets 2.3.3, 2.4.13 and 2.5.5 and says so on those criterion pages.
  • Fixed pieces: skip link, focus moves to the new h1 after a route change, "Struktura strony", the phone navigation docked at the bottom with "Więcej", the consent card, the light and dark toggle (data-theme on html, set before paint by themeInitScript).
  • The look is quiet and editorial: off-white paper, hairline rules, square cards. It reads well and says nothing about a playground.

2. Scope

  • A new design system for every page: palette, type, shapes, components, motion. One system across the app, not a different look per page.
  • Routes, content, Notion import, search, progress store and tests of behaviour stay as they are.
  • The layout of the home page and of criterion pages changes with the chosen variant. Other pages take the new components without a new layout.
  • A new "Spokój" (calm mode) switch, see section 4.

4. Shared by every variant

  • Spokój. A switch in the header (in "Więcej" on phones). It stops every animation and transition and swaps the decorative tints for plain paper. It sets data-calm on html before paint, stored in localStorage like the theme. Without a stored choice it follows prefers-reduced-motion. The point: someone sensitive to motion or colour can turn it off in one place, without system settings.
  • One code per kind of content. Kryteria, Praktyka, Ścieżki, Prawo, Symulatory, Słownik and WCAG 3.0 each get an icon, a name and a colour, the same in the navigation, search results, tiles and links "Co dalej". Colour never appears without the icon and the name (1.4.1).
  • Search everywhere. In the header of every page, with / to focus it. The shortcut is announced next to the field and can be turned off (2.1.4).
  • "Co dalej" at the end of criterion pages. The related example, lesson and stronger criterion that the page already links to, gathered in one block, so nobody has to scan the page for the next step.
  • Kept as they are: skip link, landmarks, focus after a route change, "Struktura strony", the docked phone navigation and "Więcej", the consent card, the 3 px focus outline, monospace for codes, and the marker meaning "what the user gains" (pear in A, orange in B, yellow in C, a coral bar in D, yellow in E).

5. Motion

Motion is what makes it a playground, so every variant has some. It is also what most often hurts neurodivergent readers. Rules for all five:

  • Only in response to the reader, or once when a page loads. Nothing loops, nothing moves on its own after the first second, no parallax, no scroll-jacking.
  • Only transform and opacity, at most 620 ms, no flashing.
  • Spokój and prefers-reduced-motion turn it all off (2.3.3). Nothing depends on motion: every state shows without it.

6. Accessibility

Read against docs/accessibility.md. The new parts and what they need:

  • Contrast. Every text pair in all seven variants and both modes was computed in OKLCH: text 7:1 or more (body text in A light 7.8:1, secondary text in B light 7.4:1, the lowest is 7.2:1 in A dark). Text on coloured fills: dark ink on pear 12:1, on orange 7.6:1, on the C bricks 7.7 to 12.4:1. Control borders 3.6:1 or more. D: text 7.5:1 or more (coral accent text 7.5:1, white on the coral button 8.4:1), control borders 4.2:1. E: text 7.8:1 or more, links 7.8:1 in light and 8.9:1 in dark. F and G: text 7.3:1 or more; the cyan second headline line is large text and meets 4.5:1 (1.4.6 for large text). That keeps 1.4.6, which the app claims today.
  • Targets. 44 px or more for every control and link in navigation, 32 px for chips with spacing (2.5.5 and 2.5.8).
  • Focus. 3 px outline with a 2 px gap, in a colour at 3:1 against both the page and the control (2.4.13): navy in light, yellow in dark. E uses the public-service style instead: a yellow fill with a thick ink bar under the focused element, the same in both modes.
  • Literal names first. The playground is in the shapes and the motion, never in the names. Places on B's map are called "Kryteria" and "Prawo", not "Huśtawki"; the sandbox, map and bricks are decoration. Metaphors are hard for some autistic readers, so they never carry information.
  • Predictable. Navigation, search and Spokój sit in the same place on every page (3.2.3), icons keep one meaning (3.2.4), nothing changes on focus (3.2.1).
  • B's map. In code it is an ordered list of links laid out with CSS grid; the chalk paths are an aria-hidden SVG. A screen reader, keyboard order and 400% zoom (1.4.10) get the same list.
  • C's filters. Real buttons with aria-pressed; the result count is announced like the criteria filters today.
  • Type. Atkinson Hyperlegible (B, and mono in C) was designed for low vision and tells apart letters that are easy to confuse (I l 1, O 0). Lexend (C) is designed for reading fluency. Plus Jakarta Sans (A) has open shapes and a large x-height. Public Sans (E) was made for US government services. Geist (D) is a neutral grotesque with a matching mono. All of them support Polish characters (checked in latin-ext).
  • Text spacing. No fixed heights on text containers, so 1.4.12 overrides do not clip.

7. Code

  • src/styles.css: new token values in the same names (--paper, --ink, --accent and the rest), plus per-section tokens (--kind-kryteria and so on), radii, shadows, easings and durations. light-dark() stays. Colours written in OKLCH.
  • design.md at the root: the chosen system in Hallmark's format (palette, type, shapes, motion, what pages share). Every later UI change reads it first.
  • Fonts through @fontsource packages, replacing @fontsource-variable/inter. Package names are confirmed when installing.
  • New: src/components/calm-toggle.tsx with a calmInitScript next to themeInitScript, and a @custom-variant calm in CSS. A kind map in src/lib/ (name, icon, token per kind of content), typed from the existing section list.
  • Changed: site-header.tsx (search, Spokój; in B the rail), site-footer.tsx, routes/index.tsx, routes/kryteria/$criterionId.tsx, level-badge.tsx, fix-card.tsx, filters.tsx, paths.tsx. No file is deleted.
  • No motion library: CSS transitions, @keyframes and @property for the counter.

8. Rollout order

  1. Pick a variant (or a mix) in the mocks.
  2. Tokens, fonts, design.md. The app looks different but keeps every layout. Axe and Playwright tests pass.
  3. Spokój and the content-kind map.
  4. Header, footer and phone navigation.
  5. Home page.
  6. Criterion pages.
  7. The remaining pages take the components: criteria list, practice, patterns, before and after, paths, law, simulators, glossary, search, contact, privacy.
  8. Screenshots in docs/screenshots/ refreshed, outdated ones deleted, README updated.

Every step is a working app. Steps 2 to 7 can each be a separate pull request.

10. Decisions

  1. Which variant: A to G, or a mix (name the parts). D and E can also take one playful piece from A to C, for example C's progress tower in E.
  2. Which favicon: idea 1 (in F and G), 3, or another.
  3. For F: keep the SVG illustration, or commission one like the concept's 3D scene?
  4. Should Spokój start on for everyone, or only with prefers-reduced-motion? I propose: only with the system setting.
  5. For C: dark-first as in the mock, or follow the system as today? I propose: follow the system, the mock only shows dark first.
  6. The home page headline "Zacznij od tego, co psuje najwięcej." stays in A; B to E propose new ones. E's "Nowość" banner is an example and needs a decision on who keeps it current. Copy changes go through you with wording variants in chat.
  7. B's "Trasa na 15 minut" needs a real figure from the lesson lengths, or loses the number.
