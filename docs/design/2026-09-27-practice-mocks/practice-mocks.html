Rows grouped by topic: images, keyboard and focus, forms, appearance, motion. Each row names the problem, the fix in one line, the criteria and the effort. Dense and scannable; works like the criteria list the reader already knows. No pictures of the fault.

B: Cards ordered by payoff

The "napraw to najpierw" cards from the reworked home screen (screen 0 of variant A), as the catalogue. Each card shows a small static picture of the fault, the fix, and on a yellow edge what the user gains. Ordered from cheapest fix with the biggest gain. The most visual and the most persuasive; the pictures are decorative and hidden from screen readers, so the text must carry everything.

Reference: the example page

Adapted from screen 3. Both variants render in sandboxed iframes with their own title, so the broken one cannot leak into this page's accessibility tree and neither picks up the app's styles. Examples that move or change on their own, such as the carousel, start only after "Uruchom przykład", because our own page must still meet 2.2.2. The code sits in a disclosure under each variant and is the same file the iframe renders, so it cannot drift from the demo. The simulator buttons from screen 3 come in phase 7.
